# یادگیری شخصی، آزمون‌ها و محدودیت‌های اعتبارسنجی

## قابلیت یادگیری
- مدل **kNN نظارت‌شده و کاملاً آفلاین** بر پایهٔ انرژی RMS و BPM تخمینی است؛ نه مدل از پیش آموزش‌دیدهٔ تشخیص احساسات.
- فقط آهنگ‌هایی که کاربر خودش دستی خانهٔ Mood آن‌ها را انتخاب کرده و تحلیل صوتی دارند، نمونهٔ آموزشی هستند.
- حداقل پنج آهنگ با حداقل دو برچسب متفاوت لازم است؛ آهنگ‌های نامطمئن با فرض خنثی جای‌گذاری می‌شوند.
- برچسب‌ها روی دستگاه ذخیره می‌شوند؛ دکمهٔ Reset فقط برچسب‌های آموزش مدل را پاک می‌کند، نه تخصیص‌های دستی فعلی.
- این روش **احساس واقعی شنونده** یا هیجان قطعی موسیقی را اندازه‌گیری نمی‌کند.

## آزمون خودکار
1. JUnit: منطق kNN، موارد امتناع از طبقه‌بندی، ورودی خراب و تست‌های قدیمی.
2. Emulator smoke: اجرای MainActivity و نمایش صفحه اصلی بدون الزام مجوز فایل صوتی.
3. بررسی ایستای امنیت: اجازه‌های لازم، بکاپ، HTTP بدون رمز و اجزای exported.
4. Gradle: testDebugUnitTest و assembleDebug.

## آزمون دستگاه و باتری
اجرای واقعی روی گوشی در محیط این گفتگو ممکن نیست. ابزار قابل تکرار:
```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
DURATION_MINUTES=60 bash tools/device_qa.sh
```
در شروع، پلی‌لیست محلی را روی گوشی پخش کنید. گزارش‌ها شامل مدل دستگاه، نسخهٔ اندروید، حافظه در هر دقیقه، وضعیت باتری، batterystats، logcat و زنده‌بودن پردازش‌اند.

### آزمون دستی لازم برای پذیرش
- تعویض خروجی هدفون، بلوتوث و اسپیکر، قطع ناگهانی اتصال.
- تماس ورودی و Audio Focus؛ قفل صفحه و کنترل اعلان.
- شبکه خاموش، فضای ذخیره پر، فایل پاک‌شده و فایل خراب.
- فونت بزرگ، TalkBack، چرخش صفحه و کنترل هر صفحه و زیرصفحه.
- پخش حداقل ۶۰ دقیقه، تعویض ۲۰۰ آهنگ و مقایسهٔ باتری تحت شرایط یکسان.
- ممیزی امنیت پویا و کتابخانه‌های بومی FFmpeg.

**محدودیت:** تست روی emulator جایگزین ارزیابی جامع UI/UX، پایداری و مصرف واقعی باتری روی دستگاه فیزیکی نیست.
